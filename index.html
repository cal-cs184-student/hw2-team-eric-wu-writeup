Section I: Bezier Curves and Surfaces

Part 1: Bezier curves with 1D de Casteljau subdivision

In this part, de Casteljau's algorithm is used to evaluate a Bezier curve. The algorithm works by doing linear interpolation along adjacent pairs of a list of N control points, to generate a list of N-1 control points. This is then repeated until you are left with only one point, which is a point along the Bezier curve.

To generate all points along the curve, the algorithm is applied with a varied parameter for the linear interpolation.

Part 2: Bezier surfaces with separable 1D de Casteljau

When we can evaluate a Bezier curve, this gives us a way to extend de Casteljau's algorithm to evaluate a points on a Bezier surface. A point on a N x N Bezier surface can be evaluated by first evaluating each row of points, to get N points along each row. This evaluation is done with a parameter u. Then, a separate parameter t is used, treating these N points as the control points of a bezier curve. This finally gives us a point at (u, v) on the Bezier surface.

Section II: Triangle Meshes and Half-Edge Data Structure

Part 3: Area-weighted vertex normals

This section asks us to implement area-weighted vertex normals. I implemented weighting by area by simply looping through all adjacent half edges of the vertex, and collecting the positions of neighbor vertices of the target vertex. Then, I would take the cross product of adjacent neighbors, and keep track of the sum of all cross products.

Recall that the cross product's magnitude is proportional to the area spanned by the parallelogram enclosed by the two vectors, which means that it is also proportional to the area of the face (assuming all faces are triangles). This means we only need to normalize the sum at the end, to get an area-weighted sum of all normals of all faces.

Part 6: Loop subdivision for mesh upsampling

Implementation notes

To implement loop subdivision, I followed the 5 step procedure outlined in the comments of the code.

For each vertex, I walked its neighbors, counting degree and summing neighbor positions. I computed newPosition for each vertex as described, and set isNew = false.

For each edge, I computed the edge's newPosition, which would be used later.

I iterated over only the original n edges of the mesh, saving nextEdge before each splitEdge call (to avoid problems with iterator invalidation). I split each edge, and for the returned vertex, I set isNew = true and newPosition = e->newPosition. I also modified the splitEdge routine to mark the correct edges as new/old: the two cross edges are new, and the two halves of the split edge are old.

I flipped every edge in the mesh with e->isNew == true that connects one old and one new vertex.

Finally, I assigned position = newPosition for all vertices of the mesh.

When implementing this part, I was originally unaware of needing to mark edges as new/old based on where they came from each edge split. I was originally check every single edge in the mesh, and flipping them if they joined a new and old vertex, which created a very ugly result. I caught this issue by printing some sanity checks, and noticing that I was actually flipping every single edge of the mesh.

Observations on the effect of subdivision

Loop subdivision is approximating, not interpolating, so the surface shrinks toward its control mesh's interior and the mesh becomes smoother and rounder with each iteration. Sharp corners and edges get rounded off. A cube becomes a blob after a few subdivisions. Corners with lower degree (such as a cube vertex of degree 3) are pulled inward the most.

I found that one way to make the cube subdivide symmetrically is to subdivide each edge that lies along a face, so that each face consists of 4 triangles that divide the face symmetrically. Since each vertex is symmetric after this step, this causes the subdivision to continue to be symmetric.
